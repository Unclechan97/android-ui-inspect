# 小红书采集配方（可选）

本文件是 [android-ui-inspect](../SKILL.md) 的 App 特化参考。只在用户明确要在小红书里做**只读**采集时读取。遵守主技能的安全边界：不点赞、不收藏、不关注、不发私信、不代输手机号；**不自动唤醒或解锁**，运行前由用户手动解锁。

包名：`com.xingin.xhs`

---

## 1. 搜索

短关键词比长句更稳（长句容易把搜索结果变成模板文案检索，噪音大）。常用：

```bash
KW=$(python adb_ui.py quote "深圳找对象")
python adb_ui.py open "xhsdiscover://search/result?keyword=$KW" --serial <SERIAL>
```

也可以直接搜“深圳女找男”“相亲贴”“找男朋友”等短词。

搜索页 dump 能读到：笔记标题、作者昵称、点赞数、相对日期。结果页是瀑布流，图片加载会引起重排；**每次点击前重新 dump，不要用几十秒前的坐标**。稳妥做法：

1. `dump` 找到目标卡片标题（不是作者昵称）的 box；
2. 点标题文字区域（不要点卡片边缘）；
3. 打开笔记后先确认作者昵称和标题，防止点错卡片；
4. 进入主页后核对小红书号与笔记是否对应。

搜索页可能混有广告、群聊招募、“脱单机构”帖子；不要把它们当作个人。

---

## 2. 笔记页 → 主页

笔记页可读：作者昵称、正文、点赞/收藏/评论数、发布时间（有时在正文下方或评论页）。

打开作者主页有两种方式：

- 点笔记页左上角作者头像；
- 如果头像没有可读标签，先从 dump 找到头像节点的 box，再取中心点。

**混合树坑**：从笔记头像进入主页时，dump 可能同时包含底层的笔记页和新的主页分支。先看当前 package、页面标题和节点层级，按主页根节点收窄范围，不要把整棵树都当成主页字段。容器和子节点有时有相同的文字和 bounds；脚本会优先保留可点击副本，但读取字段时仍要按来源去重。

**1080×2340 的 MI 9 实测坐标（仅作示例，绝不能跨设备硬编码）**：

- 作者头像区域：`(81,75)-(246,229)`，中心约 `(160,150)`；
- 返回箭头：`(41,127)-(68,176)`，中心约 `(60,130)`——**这里是返回，不是头像**，很容易点错。

在其它分辨率/机型上，坐标会变。优先用 `dump` 找头像节点的 bounds/content-desc，再取中心点。**不要用昵称搜索来定位账号**：小红书昵称重名很严重（同一昵称可能有七八个账号），从当前笔记点头像进入、再核对小红书号，才可靠。

主页可读字段：

- 昵称；
- 小红书号（稳定 ID）；
- IP 属地（如 `IP：广东`）；
- 性别/年龄（如果用户填写了）；
- 关注 / 粉丝 / 获赞与收藏；
- 个性签名；
- 笔记瀑布流：标题、点赞数、相对日期（如“3 天前”“09-13”）；超过一年会显示年份。

**同名问题**：昵称可能重名，不要只靠昵称定位。用“头像进入 + 小红书号 + 笔记标题/日期”三件套核对。

## 3. 评论区

打开评论：笔记页底部的“评论 N”按钮。**不要记固定坐标**，用 dump 找文本：

```bash
python adb_ui.py dump --serial <SERIAL> --contains 评论
python adb_ui.py find "评论" --serial <SERIAL>
```

如果使用示例设备（1080×2340）：笔记页评论按钮常在底部右侧，约 `(905,2142)`；从主页浮层打开评论时约 `(368,2142)`。仍要先 dump 验证，页面布局/版本更新会变。

评论页可读：

- 评论者昵称；
- 评论正文；
- 时间 + IP 属地（如“09-09 广东 回复”）；
- 点赞数；
- “展开 N 条回复”；
- 置顶评论通常带“置顶”标记。

需要注意的信号：

- 置顶评论是广告、群聊、联系方式、机构招募；
- 评论区大量“报名”“dd”“求带”“已私”；
- 作者只回复带联系方式的人，或引导加群/私信；
- 评论者主页是空号/风险号/营销号。

评论者头像也可以点进主页；这是找人的有效入口，但点之前先确认是头像节点，避免误点。

**评论面板的坑**：

- 返回键可能把评论面板和笔记一起关掉。只想回到评论顶部时，在面板内部向下滑（把内容往回拉），不要按返回。
- 评论顺序、展开状态和广告插入都会变化；旧坐标不可复用。每次按“昵称 + 正文”重新 dump 定位。
- 同一篇笔记里候选很多时，先记录昵称/正文/时间，再点头像；不要连续快速点多个头像。
- 如果评论按钮或评论正文定位不到，先重新 dump 并确认还在评论面板；仍失败就跳过这篇，不要用旧坐标硬点。

## 4. 导航与深链的坑

- 深链搜索可能重置任务栈。按返回键不一定回到搜索结果，可能回到之前的某个主页。
- **搜索结果可能换批**：重新执行同一条深链、从后台切回、或隔一段时间再进搜索页，结果都可能被重新排序/换一批。一次搜索就是一个批次：批次内连续处理；不要拿上一批的卡片列表来点这一批，否则大量“已下沉/删除”。
- 如果只是需要重看当前搜索结果，优先用页面内的滚动回到顶部，而不是重新发深链；如果确实要刷新，就接受这是新批次，重新 dump、重新记录。
- 页面切换/加载后，旧的 bounds 全部失效；重新 dump。
- 屏幕锁定后 dump 只能看到锁屏节点（可能只有 2 个）。先运行 `python adb_ui.py screen` 只读检查；如果锁屏或息屏，请用户**手动**点亮并解锁。本技能不会自动唤醒/解锁，也不要发送电源/唤醒键。
- 误触点赞/收藏：先 dump 确认状态，不要连续乱点；是否取消由用户决定。
- 点“返回”后如果 App 状态不对，用 `app stop com.xingin.xhs` 停掉再让用户重开（风控时也可这样停手）。
- 同一时间只开一个采集会话，不要并发操作同一台手机。

## 5. 可选：相亲号真伪初筛

以下是用户侧的经验规则，只能作为**初筛信号**，不能证明 100% 真假：

1. **置顶评论广告**：置顶评论本身或置顶评论的回复里有广告、群聊、机构、联系方式。
2. **主页全是相亲贴且间隔很近**：翻几页都是同一类“找对象”帖子，发帖时间密集。
3. **新号连续发帖**：新注册账号在很短时间内连发多篇，间隔小于一周；真实、普通的找对象者通常赞数不高、主页显得日常。
4. **模板复用**：多篇笔记/多个账号使用相同句式，只替换身高、城市、职业等槽位。
5. **IP 与自称地点不符**：自称深圳，IP 在外省，且没有近期来深证据。
6. **评论区“报名”**：同一账号在多个相亲贴下复制“报名”“dd”，或作者只对“报名”类评论热情。
7. **风险提示**：主页显示“该账号疑似存在风险，暂时无法查看笔记”，直接排除。
8. **互关/营销特征**：关注数和粉丝数都很高（如几千），但几乎没有自己的日常笔记，或只有很久以前的一条。
9. **引流特征**：主页混有“去水印”“画质修复”“电商教程”等 SEO 内容，同时置顶一篇相亲贴，可能是运营号。

相对可信的信号：

- 主页有生活内容（吃饭、旅行、工作、宠物等），不全是相亲贴；
- 相亲贴写具体、能对上主页信息，而不是纯槽位模板；
- 赞数普通，评论里是正常男生自荐；
- 作者用自己的话回复，不是统一话术；
- IP、所在地、工作地点互相一致。

这些只是降低风险，不是身份认证。最终应由用户通过语音/视频/线下见面核实；不要替用户保证“真人”。

## 6. 从评论区找人

男生发的相亲贴，评论区常有女生自荐。流程：

1. 打开帖子评论；
2. 找女生自荐评论（例如“97 女，深圳工作，本科，蹲一个奔结婚的”）；
3. 点头像进主页；
4. 核对 IP、主页笔记、发帖时间、小红书号；
5. 回帖子确认她没有留广告/群聊；
6. 记录证据和时间。

注意：

- 默认昵称（“小红薯”+ 编号）不一定是假号，但可能是新号/风险号；必须进主页看。
- 高互关（几千关注/几千粉丝）而内容很少，通常是互粉/营销号。
- 风险提示账号直接排除。
- **来源要隔离**：作者帖正文里的“女/男/地区”只能用于作者本人；评论者只看其评论和主页，不能把原帖正文套到评论者身上。
- 性别判断优先看主页的显式标注（性别年龄、简介、本人笔记）；没有就标“未知”，不要猜。
- “确认”只代表公开证据较完整，不是身份认证；最终仍需用户自行核实。
- 只读浏览，不要批量私信或骚扰。

## 7. 记录模板

```text
昵称：
小红书号：
IP 属地：
地区/年龄/性别（主页公开的）：
关注 / 粉丝 / 赞藏：
意向证据：<自己的笔记标题 + 时间 + 赞评数> 或 <评论原文 + 时间>
主页内容：<生活/写真/工作/相亲等类型 + 时间分布>
置顶评论检查：<无广告 / 有广告/群聊/报名 —— 具体原文>
风险信号：<模板复用/IP 不符/风险提示/引流内容/无>
结论：确认 / 待定（缺什么证据）/ 排除（原因）
抓取时间：YYYY-MM-DD HH:MM
```

**时间换算**：把“3 天前”“昨天”按抓取日期换算成绝对日期；不确定就标“约”。不要编造看不到的信息。

## 8. 风控停手

小红书常见限制：手机号绑定墙、登录弹窗、验证码、“操作频繁/系统繁忙”、账号风险提示。处理：

1. 不输入手机号/验证码/密码；
2. 不点弹窗中的确认/绑定按钮；
3. 能安全返回就返回一次；否则 `python adb_ui.py app stop com.xingin.xhs`；
4. 等 10–30 分钟，再问用户是否继续；
5. 记录触发了什么，不要反复试；**不要用自动化处理验证、申诉或“解除限制”**，交还用户手动处理。

低频率操作：每次点按/翻页后 1–3 秒；不要连续快速滑几十屏；单次会话采集够用就停；账号出现风险提示后，当天不要再继续。
